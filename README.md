# telegaNEW

Неофициальный Telegram для Android, который подключается там, где обычный
Telegram режут.

telegaNEW — форк [ZaStoGram](https://git.zapret.moe/zastogram/ZaStoGram), а тот,
в свою очередь, форк официального [Telegram для Android](https://github.com/DrKLO/Telegram).
Аккаунт, чаты и серверы — обычные телеграмовские, меняется только то, как
клиент до них добирается и как держит соединение. Сейчас основа — Telegram 12.10.4.

## Скачать

Свежие сборки лежат в [релизах](https://github.com/Arseniy07955/telegaNEW/releases).
Каждый релиз содержит четыре APK — нужен один, под процессор телефона:

| Файл | Для чего |
| --- | --- |
| `TelegaNEW-standalone-arm64-v8a.apk` | почти все телефоны последних лет — **бери этот, если не знаешь** |
| `TelegaNEW-standalone-armeabi-v7a.apk` | старые 32-битные телефоны |
| `TelegaNEW-standalone-x86_64.apk`, `…-x86.apk` | эмуляторы и редкие планшеты на Intel |

При первой установке Android попросит разрешить установку из этого источника.
Дальше обновления приходят сами — вручную ничего качать не нужно. При обновлении
Google Play Защита может предложить проверить приложение («Проверить») — это
штатное поведение для всего, что не из Google Play.

## Что внутри от ZaStoGram

Основная работа по обходу блокировок сделана в ZaStoGram, и она вся здесь:

- **маскировка MTProxy** — рукопожатие FakeTLS (`ee`-секрет) похоже на обычный
  HTTPS из браузера, а не на типичный трафик Telegram;
- **веб-прокси** (`t.me/webproxy?…`) — трафик идёт через HTTPS-страницу-мост;
- **WSS-транспорт** — подключение к Telegram через WebSocket-релеи
  (в telegaNEW выключен по умолчанию, см. ниже);
- **плагины** на Python (совместимы с exteraGram) и настройки приватности.

Техническое описание всего этого — в [docs/ZaStoGram.md](docs/ZaStoGram.md).

## Чем отличается от ZaStoGram

**Свои обновления.** Приложение проверяет новую версию при запуске, а вручную —
через *Настройки → Проверить обновления*. Скачивается APK именно под архитектуру
телефона.

**Прокси прилетают с сервера.** Вместе с проверкой обновлений клиент забирает
актуальный список прокси (обычные и веб): новые точки добавляет, у старых
обновляет секрет, отмеченные на удаление убирает. Пользователю не нужно искать
прокси по каналам. Список ведёт [бот](#бот-со-списком-прокси) и кладёт в
`proxies.json`; если файла нет, берётся запасной список из `update.json`.

**Умный подбор прокси.** Если соединение не поднялось за 4 секунды, клиент
проверяет до четырёх запасных точек и садится на первую ответившую. Для
веб-прокси, которые держат локальный мост открытым и потому не «ждут TCP»,
перебор стартует через 20 секунд. Точки, помеченные как приоритетные, пробуются
первыми. Раз в 20 минут пинги освежаются, чтобы следующий выбор не был вслепую.
Рабочую точку клиент не бросает.

**Уведомления в свёрнутом виде.** Пуши Google (FCM) до неофициальных сборок не
доходят, поэтому с первого запуска включено фоновое соединение (Keep-Alive и
«Не усыплять сеть в фоне»). Цена — постоянная строка в шторке. Отключается в
*Настройки → Уведомления и звуки → Keep-Alive Service*. Если на телефоне стоит
дистрибьютор [UnifiedPush](https://unifiedpush.org/) (например, ntfy), пуши
идут через него.

**WSS выключен по умолчанию.** В ZaStoGram он включён, но в России релеи
Telegram и запасной туннель через Cloudflare чаще недоступны, и попытки через
них только задерживают подключение. Включается в настройках прокси.

**Маскировка настроена на скорость и стабильность.** Всё, что замедляет уже
установленный поток (размер TLS-записей, паузы, стартовая маскировка),
выключено; параллельных каналов меньше; TLS-профиль — *Auto rotate*.
Фрагментацию ClientHello, смену TLS-профиля и более тихий темп подключений
клиент включает сам для конкретного прокси, если рукопожатие с ним сбоит.

**Своё оформление.** Название telegaNEW, свои иконки и бот
[@SenkapopkaVpnBot](https://t.me/SenkapopkaVpnBot) в списке чатов.

**Один раз покажем канал нового клиента.** Над списком чатов появляется
плашка с предложением заглянуть в [@yonsegram](https://t.me/yonsegram) — клиент
YonSeGram на базе telegaNEW. Она показывается один раз, закрывается кнопкой
«Не сейчас» и отключается в *Настройки → ZaSto Приватность → «Предлагать канал
@yonsegram»* (выключить и снова включить — плашка покажется ещё раз).

## Для владельца форка

### Обновления: `update.json`

Файл лежит в корне репозитория. При каждой сборке CI выкладывает его на S3,
откуда его читают все установленные клиенты.

```json
{
  "version_code": 0,
  "version_name": "dev",
  "changelog": "• Обновление",
  "proxies": [
    { "server": "pokemon.catpaws.ru", "port": 9443, "secret": "ee…", "priority": true, "active": true },
    { "server": "37.139.34.199", "port": 443, "secret": "ee…", "delete": true }
  ],
  "web_proxies": [
    { "server": "web.example.com", "secret": "dd…", "priority": true }
  ]
}
```

- `version_code`, `version_name` — **руками не трогать**: CI проставляет их от
  текущей сборки (`12.10.4.<номер запуска>`), иначе клиенты не увидят обновление.
  Имя версии должно быть из чисел через точку, иначе клиент падает при сравнении.
- `changelog` — текст в окне обновления.
- Списки прокси здесь — **запасные**: их читают клиенты, у которых нет
  `proxies.json`, и старые версии. Актуальный список ведёт бот (ниже).

### Список прокси: `proxies.json`

Файл `proxies.json` лежит на S3 рядом с `update.json` и не зависит от него: релиз
сборки его не затирает, а если `update.json` убрать (поставить обновления на
паузу), прокси всё равно раздаются. Формат тот же — `proxies` и `web_proxies`:

- `server`, `port`, `secret` — из ссылки `t.me/proxy?server=…&port=…&secret=…`;
  у веб-прокси порта нет, адрес может содержать путь (`host/path`);
- `priority` — точку пробуют первой при подборе;
- `active` — включить эту точку, если у пользователя прокси выключен или его
  точка исчезла из списка. Работающий прокси пользователя не перебивается.
  Веб-прокси лучше не делать активным, пока все не обновились до версии с
  перебором для них;
- `delete` — убрать точку у всех. Запись со `delete` держим в списке две
  недели, пока все клиенты не обновятся.

Веб-прокси лежат в отдельном массиве `web_proxies`: у них нет порта, и старые
клиенты оборвали бы чтение всего списка на такой записи.

### Бот со списком прокси

Бот хранится отдельно от этого репозитория и крутится в Docker на домашнем
сервере: проверки идут из домашней сети, то есть так, как прокси видит
пользователь в России.

- присылаешь ему ссылки `tg://proxy…` / `tg://webproxy…` (можно пачкой) — он их
  добавляет, проверяет и сразу выкладывает `proxies.json`;
- список, приоритет, активный прокси, перепроверка, удаление — на кнопках;
- раз в 15 минут проверяет все прокси: у `ee` — полное рукопожатие FakeTLS
  (ключ проверяется по подписи сервера), у остальных — TCP, у веб-прокси —
  загрузка страницы-моста;
- прокси, не отвечающий 24 проверки подряд (около 6 часов), убирает: сначала с
  пометкой `delete` на 14 дней, потом совсем;
- не удаляет последний живой прокси и не считает ошибки, если не работает сеть
  самого бота;
- слушает только Telegram-ID владельца, ключи от S3 хранит в `.env` на сервере.

Ограничение: у `dd` и обычных секретов бот видит только открытый порт, поэтому
прокси, который принимает соединение, но не отвечает, он не заметит — такие
убирай вручную кнопкой «Убрать».

### Сборка в GitHub Actions

APK собирает [`build-apk.yml`](.github/workflows/build-apk.yml): автоматически на
каждый push в `master` или вручную кнопкой *Run workflow*. Сборка идёт около
10–25 минут. **Публикуется только `master`**: пре-релиз на GitHub и файлы на S3
(APK, `update.json`) появляются только после сборки этой ветки. С остальных
веток идёт только сборка без выкладки — на них удобно проверять изменения на
телефоне. Коммит с `[skip ci]` в сообщении сборку не запускает.

Секреты в *Settings → Secrets and variables → Actions*:

| Секрет | Зачем |
| --- | --- |
| `TELEGRAM_API_ID`, `TELEGRAM_API_HASH` | свои ключи с [my.telegram.org](https://my.telegram.org); без них сборка идёт с тестовыми |
| `KEYSTORE_BASE64`, `KEYSTORE_PASSWORD`, `KEY_PASSWORD`, `KEY_ALIAS` | подпись APK. Ключ нельзя менять: APK с другой подписью не встанет поверх старого |
| `S3_HOST`, `S3_USER`, `S3_PASS` | выкладка APK и `update.json` на S3 |

### Локальная сборка

Одна архитектура на своём компьютере, без публикации — повторная сборка после
правки Java занимает около 2–3 минут (в Actions — 10–25).

```powershell
powershell -File Tools\build-local.ps1 -Install -StopDaemon
```

Скрипт собирает arm64-v8a, кладёт APK в `dist-local\`, по `-Install` ставит его
на телефон по adb, по `-StopDaemon` закрывает Gradle (он держит около 9 ГБ
памяти; без ключа закроется сам через 10 минут простоя).

Что нужно один раз:

- JDK 17 (`C:\Program Files\Java\jdk-17`), Android SDK с NDK 27.2 и CMake 3.22;
- сабмодули: `git submodule update --init --recursive --depth 1`;
- **VPN при первой сборке**: Python-библиотеки для плагинов качаются с
  `chaquo.com`, а оттуда без VPN идёт 200–300 байт/с и pip падает по таймауту.
  Дальше всё кэшируется. Для `dl.google.com` скрипт сам подключает зеркало
  ([`gradle-mirror.init.gradle`](Tools/gradle-mirror.init.gradle)), `-NoMirror`
  отключает его;
- файл `local-build.env` рядом с репозиторием (он в `.gitignore`):

```
TELEGRAM_API_ID=...
TELEGRAM_API_HASH=...
KEYSTORE_PATH=C:\путь\к\release.keystore
KEYSTORE_PASSWORD=...
KEY_ALIAS=zastogram
KEY_PASSWORD=...
```

Ключ нужен тот же, что в `KEYSTORE_BASE64`, и хранить его надо **вне**
репозитория. Сборка с другим ключом не встанет поверх приложения из GitHub
(придётся удалить его вместе с данными). Номер сборки скрипт берёт по последнему
запуску в Actions, чтобы следующая сборка из GitHub была новее локальной.

### Как подтянуть обновления ZaStoGram

```bash
git fetch upstream
git log --oneline HEAD..upstream/master
git checkout -b merge-upstream
git merge upstream/master
```

Сначала слей в отдельную ветку и собери её вручную (*Run workflow*): она соберётся,
но не опубликуется. Проверь на телефоне и только потом влей в `master` — любой
push туда сразу уходит всем пользователям.

При конфликтах не забирай свою старую версию файла целиком: так в прошлом уже
терялись апдейтер, строки и настройки. Бери версию апстрима и переноси поверх
только свои правки. Исключение — `README.md`: он у нас свой, а изменения
апстримового README переносятся в [docs/ZaStoGram.md](docs/ZaStoGram.md), по
нему сверяются проверки в `Tools/`. Перед пушем полезно прогнать проверки:

```bash
python3 Tools/check_mtproxy_all.py
```

Часть проверок падает и на чистом апстриме или сверяет бренд ZaStoGram — это
известный шум, сравнивай с тем, что было до слияния.
